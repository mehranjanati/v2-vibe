### P0.3 — Control-plane auth boundary

- **id:** P0.3 · **phase:** P0 · **title:** Control-plane auth boundary · **status:** `implemented_unverified`.
- **Goal:** every mutating control-plane route enforces an explicit session/ownership check.
- **Why:** Edge auth does not protect Go; without this, multi-tenancy is fiction.
- **Dependencies:** P0.9 decision informs the final mechanism; the provisional check landed first (see notes).
- **Affected files:** `backend/pkg/api/auth.go`, `backend/pkg/api/routes.go`, `backend/pkg/api/auth_test.go`, `backend/pkg/cloudflare/kv.go`, `backend/pkg/engine/hub.go`, `backend/cmd/main.go`, `src/services/controlPlaneClient.ts`, `src/lib/control-plane-session.ts`, `src/lib/api-client.ts`, `src/contexts/auth-context.tsx`, `worker/types/auth-types.ts`.
- **Implementation notes:** `sessionGuard` (`backend/pkg/api/routes.go`) now runs `RequireSession` (`backend/pkg/api/auth.go`) in front of the seven routes at `backend/pkg/api/routes.go:305`, `backend/pkg/api/routes.go:308`, `backend/pkg/api/routes.go:311`, `backend/pkg/api/routes.go:315`, `backend/pkg/api/routes.go:318`, `backend/pkg/api/routes.go:324`, `backend/pkg/api/routes.go:325` (`POST /api/agent/session`, `GET /api/agent/:id/connect`, `POST /api/projects/:id/deploy`, `GET /api/projects/:id/files`, `POST /api/projects/:id/github-export`, `POST /api/workflows/trigger`, `GET /api/workflows/:workflowId`). Token sources: `Authorization: Bearer`, `X-Session-Token`, `access_token` cookie (P0-SEC-009: the Edge cookie name; a cookie-authenticated request additionally needs a trusted Origin). Provisional verifier = `EdgeKVVerifier` reading `session:token:<token>` from the Edge `VibecoderStore` KV namespace (`backend/pkg/cloudflare/kv.go`), i.e. the split is **contracted** (Edge stays the identity authority), not unified — the P0.9 record still owns the final choice. ### P0.5 — WebSocket authorization

- **id:** P0.5 · **phase:** P0 · **title:** WebSocket authorization · **status:** `implemented_unverified`.
- **Goal:** ticket or session gate on WS upgrade.
- **Why:** `GET /ws/:id` (`backend/pkg/api/routes.go:331`) upgrades without any ticket/session check.
- **Dependencies:** P0.3.
- **Affected files:** `backend/pkg/api/routes.go`, `backend/pkg/api/auth.go`, `backend/pkg/api/ws_auth_test.go`, `backend/e2e/p05_ws_auth_test.go`, `src/services/controlPlaneClient.ts`.
- **Implementation notes:** the upgrade route installs `wsGuard` (`backend/pkg/api/routes.go:465`) before `websocket.New`. Like `sessionGuard` it is a no-op when no `SessionVerifier` is installed (pre-P0.5 behaviour preserved); when the boundary is on it runs `RequireWebSocketSession` (`backend/pkg/api/auth.go:278`), which shares `RequireSession`'s fail-closed contract. A WebSocket handshake cannot set headers, so the browser credential travels as the `ticket` query parameter — since P0-SEC-008 that is a short-lived single-use ticket (15s, bound to the caller and room) minted by `POST /api/ws-ticket`, not the session token; `Authorization: Bearer`, `X-Session-Token` and the `access_token` cookie remain available as header transports (`wsTokenFromRequest`, `backend/pkg/api/auth.go`). `buildWebSocketURL` (`backend/pkg/api/routes.go`) mints a ticket when the request is authenticated (bare URL when the boundary is off), and the SPA fetches one per connect (`getWsTicket` / `openControlPlaneSocket` in `src/services/controlPlaneClient.ts`). The upgrade route also runs `wsOriginGuard` (foreign Origin → 403) and the P0-SEC-003 ownership guard. Rejections are 401 (missing/unknown/expired/replayed ticket) and 503 (store unavailable), emitted before the room is touched.
- **Acceptance criteria:** no-ticket connect rejected — a WS upgrade without a valid ticket/session answers 401 and never reaches the room; a valid ticket upgrades (101); a boundary-off deployment keeps the pre-P0.5 behaviour.
- **Verification:** `backend/pkg/api/ws_auth_test.go` green (no-ticket → 401, unknown ticket → 401, valid ticket → guard passes to the upgrader 426, five token transports, boundary-off no-op, store-outage → 503); `backend/e2e/p05_ws_auth_test.go` (build tag `e2e`: a real listener + `gorilla/websocket` dial proves no ticket → 401 with no socket, unknown → 401, valid → 101 upgrade + `agent_connected`, boundary off → 101 without a ticket) green via `go test -tags e2e ./e2e/ -run P05 -v`; `cd backend && go vet ./... && go test ./...` green; `bun run typecheck && bun run docs:check` green. NOT yet closed: the WS path is authenticated but not per-room scoped — room/tenant ownership stays on the HTTP create/connect routes (P0.4), matching P0.5's ticket/session-gate scope.
